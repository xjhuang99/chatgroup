ACTR Manual

ACTR is a group-chat platform for research. Participants join from Qualtrics, the Dashboard, or /join. AI personas can reply alongside humans in the same room.

Researcher access

Admin, Dashboard, and this Manual require sign-in. Production URL: https://group.xjhuang.com.

  • Sign in — lab super-admin (e.g. ACTR2026) or a registered researcher account. Use /login?redirect=/admin (or another path) to return after login.
  • Create researcher account — email + password; each account gets a default $200 API budget across all sessions it creates (see Usage & cost).
  • Account — registered researchers see spend vs budget on the Dashboard header and can open Account for details.
  • Researchers (admin) — super-admin only: view accounts and raise per-person budgets.

Registered researchers see only their own sessions on the Dashboard; super-admin sees all.

Quick start

  1. Sign in, then open Admin. Click ★ Example, set Min / max humans per group and persona names, then Create Session.
  2. After create, copy the Qualtrics HTML block (if Qualtrics is On) from the setup panel below the form.
  3. Participants complete the survey, chat in the embedded room, and click Next. You monitor live traffic on the Dashboard and download CSVs under Export if needed.
  4. For a quick pilot without Qualtrics: Dashboard → Sessions → join a test queue, or open /join with session_id in the URL.

Typical room layouts

The Admin form defaults to group size 1 when you click ★ Example.

  • 1 human + 2 bots: Min = max = 1, personas a and b, participant name c.
  • 2 humans + 2 bots: Min = max = 2, personas a and b, participant names c,d.

Persona names and human names must not overlap (e.g. do not use a as both a bot and a human label).

New sessions start from the ★ Example settings. Existing sessions keep their saved values until you edit them on the Dashboard.

Matching (Assignment & Condition)

Matching controls who is placed in the same group while waiting for chat.

  • Condition On (default) — only participants with the same Qualtrics condition value are matched; Assignment is locked to stratified.
  • Condition Off — FIFO = one line for everyone; Stratified = separate lines per condition bucket (if you still pass condition in the URL).
  • Forming groups — the server keeps several partial groups open. You join the first group with space (< max humans). When count ≥ min humans, that group’s chat starts. If min = max, this is fixed-size matching.

Matching decides who waits together. It does not control bot speech rules (session mode, persona delay, chain depth, etc.). Changing min/max on the Dashboard affects new joiners only (people already waiting keep their forming group).

Qualtrics condition field (★ Example default)

The ★ Example preset turns Condition On in Admin. It does not assign one fixed condition value for every respondent — you set that in Qualtrics → Survey Flow → Embedded Data, and the iframe passes ${e://Field/condition}.

Session modes

Session mode decides which personas are allowed to respond to each incoming message (from a human or, if Reply on any message is On, from another bot).

Do not confuse with persona mode. Session mode 3 = @mention only. Persona mode 3 = random skip — a different setting on each persona card.
  • Mode 1 — all bots (preset): Every persona may be queued to reply to each eligible message. Combined with persona mode 3 (skip), not every bot will actually speak every time.
  • Mode 2 — one bot per message: The system picks a single persona per message. Calmer than mode 1.
  • Mode 3 — @mention only: A persona replies only if its name or @name appears in the message text.
  • Mode 4 — parallel + refresh: All eligible personas may run in parallel (staggered by start jitter). If someone else posts while a bot is drafting, that draft is discarded; after rethink seconds the bot regenerates with a refresh note (up to max refresh attempts total tries, then the reply is skipped). See Session mode 4.

A persona never replies to its own message (reduces self-triggered chains). Session mode and persona mode are independent — e.g. mode 4 orchestration with persona mode 3 skip is valid.

Session mode 4 (parallel + refresh)

Use when you want multiple bots to feel like they are “listening” at once, without all posting identical lines after every human message.

SettingDefaultMeaning
Start jitter (sec)1.5Each bot waits a random 0…N seconds before starting its API call.
Rethink (sec)2.0After a peer’s message invalidates a draft, pause this long before regenerating.
Max refresh attempts2Total generation tries per bot per trigger (not “2 refreshes after the first”). If both fail validation/send, that bot skips that turn.

Only other participants’ messages bump the room context_version (not the bot’s own commit). Refresh notes appear in the transcript and in Qualtrics export when log mode is transcript or full.

Changing session mode on the Dashboard affects new bot turns immediately; bots already mid-draft follow the queue they started under.

Group chat flow

Session-level controls (Reply on any message, Max chain depth) sit in the AI Personas section on Admin. Per-persona Delay spaces replies; there is no separate bot cooldown or per-minute cap.

How a message flows

  1. Someone sends a line over WebSocket → saved to history and context.
  2. Session mode decides which personas are eligible (all, one, or @mentioned only).
  3. Each eligible persona runs its persona mode (delay, skip, or probability).
  4. If Reply on any message is On, each bot reply calls schedule_bot_chain with the current chain_depth. Another bot wave runs only when chain_depth < max_chain_depth (★ Example: 2 → human/opening at depth 0, then up to two bot-triggered waves at depths 1 and 2).

If the room feels noisy, lower chain depth, turn Reply on any message Off, increase each persona’s delay, raise skip rate, or switch to session mode 2.

Persona modes

Persona mode applies per persona after session mode has already decided eligibility.

  • Mode 1 — fixed delay: Always replies (after delay + typing) when eligible.
  • Mode 2 — random delay: Always replies; adds 0.5–2.5 s jitter before generation.
  • Mode 3 — random skip (preset): Each eligible message: roll against skip rate; if not skipped, reply with delay + jitter + typing.
  • Mode 4 — context chance: Auxiliary model estimates reply_p from context; the persona replies only if reply_p ≥ mode_4_threshold (default 0.5). There is no second random roll. Scores are logged when Qualtrics log mode is Full.

Qualtrics

Setup steps

  1. In Admin, set Qualtrics to On and create a session.
  2. In Survey Flow → Embedded Data, create the In and Out fields listed below (at minimum).
  3. Paste the generated HTML (script + iframe) into a Text/Graphic → HTML question.
  4. Publish and test with an anonymous link. Survey Preview often does not save transcript correctly.

When data is saved

  • Participant stays until chat duration ends → completed_full
  • Clicks Next before the room ends → left_early or no_messages
  • Closes tab or refreshes → same as Next (handoff script runs on unload when configured)
Production embed URL is typically https://group.xjhuang.com. Qualtrics cannot load localhost.

Read-only after session ends

When the scheduled chat duration expires, the participant embed switches to read-only: the input is disabled, the header shows Session ended, and prior messages stay visible. Participants can still scroll the transcript; they cannot send new lines.

  • Qualtrics On — the app still writes transcript and chat_status (and may auto-advance the survey when status is completed_full).
  • Next before time is up — handoff runs on leave; status is usually left_early or no_messages, not read-only browsing for the full duration.
  • API spend cap hit — bots stop generating new replies when a group reaches its cap; humans can usually still type until duration ends (see Usage & cost).

Dashboard Monitor remains a separate read-only view for researchers at any time.

Dashboard

Top metrics include API spend (all) and This hour — rolling estimates across all tracked LLM calls.

  • Sessions — join a queue for testing (or use /join), open published session settings (including per-session API cap / group in USD).
  • Monitor — live view of active rooms; each row shows spend vs cap ($spent / $cap). Pause / Resume stops new human messages and bot replies in that room until you resume (participants see “Chat is paused by the researcher”).
  • Export — two CSV types per session: activity (session settings + event log) and room messages (chat lines per GRP-…). Optional when Qualtrics Out fields are your primary handoff.
  • Usage & cost — see Usage & cost.

Modify a published session

Select a session → Edit → change fields → Save (read-only until you click Edit). You can adjust timing, session mode (1–4), mode 4 jitter/rethink/refresh, Qualtrics log mode, reply-on-any / chain depth, mentions, API cap per group, and persona JSON. Use Admin ★ Example when creating a new session.

What updates immediately vs later: API cap per group and session mode apply to active rooms after Save. Min / max humans only affects new joiners (people already waiting in a forming group stay put). Persona JSON affects the next bot reply. Condition On always forces stratified assignment (Assignment dropdown is locked).

Researchers see only their own sessions; super-admin sees all. Sessions without an owner (legacy) can be claimed on first Save by the logged-in researcher.

Usage & cost

Dashboard → Usage & cost tab shows estimated spend from token usage (rates ~10% above public list for DeepSeek and OpenAI models). Data is stored under config/usage_ledger.jsonl and rollups in config/usage_rollups.json.

Spend caps (two layers)

API spend is limited at two levels — whichever is hit first stops new bot calls for that scope:

  1. Per chat group — default $8 per GRP-… room (Admin API cap / group or GROUP_SPEND_CAP_USD in .env).
  2. Per researcher account — default $200 total across all sessions that account created (ACCOUNT_SPEND_CAP_USD in .env; super-admin can change per person on Researchers).
Example: one group may stop bots at $8 while the researcher still has budget left; many groups in one study share the same $200 account total. The ACTR2026 super-admin login is not subject to the $200 account cap.

FAQ

How do I watch without joining?

Dashboard → Monitor → select a room. Use Pause to freeze a live room during a class break; Resume when ready.

How do I get a researcher account?

Open /register, then sign in at /login. Super-admin manages budgets on Researchers (admin).

Can I change settings after create?

Yes, while the survey window is open: Dashboard → Published sessions → select → Edit → Save. If Save fails, read the toast message (auth, validation, or disk error).

What is session mode 4 vs mode 1?

Mode 1 queues bots serially (one room pipeline). Mode 4 runs eligible bots in parallel with refresh-on-peer — see Session mode 4.

Where is data stored?

Local JSON under db/ and activity_logs/, or MongoDB if MONGO_URL is set.

Why do bots feel robotic or talk too much?

Apply ★ Example in Admin or see Recommended defaults.

Do bots know they are talking to other bots?

No special label is shown to the model — everyone is a display name in the transcript. For human-led flow, keep Reply on any message Off.

What is the difference between session mode and persona mode?

Session mode = who may reply to a message. Persona mode = whether this persona actually replies when eligible.

Which API key do I need?

DEEPSEEK_API_KEY for ★ Example (DeepSeek personas). Add OPENAI_API_KEY only for personas set to a GPT model — see LLM models.

Why did bots stop talking mid-chat?

Check Monitor ($spent / $cap per room) and Your API budget or Account. You may have hit the $8/group limit or your $200 account total. Super-admin can raise per-group cap or per-researcher budget on Researchers.

Can participants still read chat after time is up?

Yes — the Qualtrics embed becomes read-only until they click Next or leave the page.
